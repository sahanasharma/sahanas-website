FraudCrew

Agentic AI Fraud Evaluation

Developed and tested an evaluation workflow for a multi-agent fraud investigation system using Python and GitHub, as part of the NTT DATA / NUS / Microsoft hackathon project.

Added red-team test scenarios and submitted work through a feature branch and pull request. My focus was on whether the system escalated the right cases, not just whether its output sounded convincing.

the evaluation set

60alerts evaluated
6confirmed fraud cases
100%fraud recall
30%escalation precision

Portfolio-reported test set. These results are not a claim about production performance.

How the metrics fit together +

The system escalated 20 alerts and cleared 40. Given 6 confirmed fraud cases and 100% recall, the implied counts are 6 true positives, 14 false positives, 40 true negatives and 0 false negatives.

Recall = 6 ÷ (6 + 0) = 100%
Precision = 6 ÷ (6 + 14) = 30%

The reduction from reviewing all 54 non-fraud alerts to reviewing 14 is 40 ÷ 54 = 74.1%. This is a false-positive review-volume comparison, not a general productivity guarantee.

The previous portfolio also reported approximately 20 analyst hours saved. That remains a time-saving estimate: a timing study and its assumptions were not included with the project material.

What I learned

Agent evaluation, confusion-matrix metrics, red-team testing and collaborative Git workflows.

Next iteration

Calibrate escalation thresholds, expand adversarial and non-fraud cases, and evaluate cost-sensitive trade-offs.

Offline RAG Assistants: Economics & Tennis

Built two domain-specific assistants with Ollama and ChromaDB, combining local model inference with vector-based retrieval.

Separate knowledge bases for economics and tennis allow answers to use retrieved context. Both systems are designed to run fully locally and offline, keeping source material and inference on-device.
